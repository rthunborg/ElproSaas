- [x] [Review][Decision][Med] `readCalculationDetail` swallows customer/facility/contact read errors — a transient customer read failure silently drives the VAT-display posture to a company default — `readCalculationDetail` (`src/features/calculations/read.ts`) checks `.error` on the header and sections/rows reads but never on the `customers` SELECT (`customerRes.error` is unread) nor on the `facilities`/`contacts` lookups (`const { data: fac } = ...` — no `error` destructured). Displayed öre stay engine-correct (no wrong money figure), and Story 5.4 added graceful settings-fault degradation, but the read-fault-vs-genuine-absence conflation is real and the posture default on a swallowed customer-read error is the less-safe direction. Merged: blind@primary/5-2 + blind@secondary/5-2 + edge@primary/5-2 + edge@secondary/5-2 + auditor@secondary/5-2. Recommended: fix: destructure and check `.error` on the customer, facility, and contact reads in `readCalculationDetail` and return the generic read-error state (mirroring the header/sections/rows reads) so a transient fault surfaces as an error rather than a null customer_type / blank name — do NOT let a failed customer read silently pick the company VAT posture.
- [x] [Review][Decision][Med] `rowMarginRatio` treats a null `unit_cost_ore` as zero cost (inflates margin to 100%, suppressing LOW_MARGIN) and does redundant `* quantity` arithmetic that adds overflow surface — In `src/features/calculations/readiness.ts` `rowMarginRatio` computes `sell = (unit_sell_ore ?? 0) * quantity` and `cost = (unit_cost_ore ?? 0) * quantity` then `(sell - cost) / sell`. (a) The `* quantity` factor cancels out of the ratio entirely — it is dead arithmetic whose only effect is to push `sell`/`cost` toward `Number.MAX_SAFE_INTEGER` for a large quantity, silently corrupting the ratio (the same overflow class 5.4-E2E-01 seeds for TOTAL_UNCOMPUTABLE). (b) A row with a genuinely unknown/unset cost (`unit_cost_ore = null`) reads as maximally profitable (100% margin) and never triggers LOW_MARGIN — a fail-OPEN that hides a pricing risk, the opposite of the classifier's conservative intent. Merged: blind@primary/5-4 + blind@secondary/5-4 + edge@secondary/5-4. Recommended: fix: drop the `* quantity` (compute the per-unit ratio directly from unit_sell_ore/unit_cost_ore) AND guard unsafe integers; decide null-cost policy — treat a counted row with a null `unit_cost_ore` as "cost unknown" (return null → no false 100% margin) rather than zero-cost, so an unknown-cost row does not silently pass the low-margin gate.
