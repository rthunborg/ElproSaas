### Key Insights And Patterns

**Insight 1 — Forward-dated version pins are real and adversarial reviewers get them wrong.**
The project's toolchain (Next.js 16, TypeScript 5.9) was genuinely current at scaffolding time but above adversarial reviewers' training-cutoff knowledge. Review layers flagged these as "non-existent versions." Any future adversarial review that claims a version "doesn't exist" must be cross-checked against `package.json` before acting.

**Insight 2 — Reference architecture sections, not plan numbers, in evergreen committed docs.**
Story 1.4 review found hardcoded epic/story numbers in `.env.example` and `local-setup.md` that attribute behavior to "Epic 8" or "Story 2.2" when the specs only say "architecture §6" or "first migrations story." If the plan shifts (as it already did with sprint-change-proposal-2026-06-12), those numbers go stale. Use section references; keep story/epic attributions out of docs that outlive a single planning cycle.

**Insight 3 — The `.env.example` gap was not caught until Story 1.4.**
The architecture target tree (§3) includes `.env.example` and `.gitignore` already whitelisted it, but no story from 1.1 through 1.3 created it. It arrived in 1.4 — which is the correct story for environment documentation. But the gap means Epic 2 stories can't rely on seeing `.env.example` until 1.4 is merged. This is a sequencing note, not a defect.

**Insight 4 — Scope guardrail discipline held perfectly.**
Zero deferred-module artifacts introduced across four stories and multiple review rounds. Nav config is a typed module with a commented-out Pilotstöd/Migrering entry. This is the pattern for all future scope-boundary enforcement.

**Insight 5 — Headless preview focus behavior is unreliable for a11y verification.**
`:focus`/`:hover` CSS pseudo-class behavior via headless preview is flaky when the host document lacks system focus. For focus-dependent behaviors (skip links, tooltips on icon rail), drive verification from real browser clicks or event-driven React state, and confirm positively with system focus present.

## Action Items

### Process Improvements

1. **Adversarial review ground-truth check**
   - Action: When an adversarial review layer flags a version/API as "non-existent," cross-check against `package.json` and the repo's actual pinned versions before treating the finding as actionable.
   - Owner: Dev Agent / SM review process
   - Success criteria: No adversarial-false-positive drives a code change; all dismissed findings are logged with verification evidence.
   - Apply from: Story 2.1 onward

2. **Reference architecture sections, not plan numbers, in evergreen docs**
   - Action: Committed markdown files that will outlive a single planning cycle (`.env.example` comments, `local-setup.md`, `ci.md`) must cite architecture section numbers (e.g., "architecture §6") rather than epic/story numbers when attributing forthcoming behavior to a planning artifact.
   - Owner: Dev Agent (each story's dev notes and doc authoring)
   - Success criteria: No hardcoded "Epic N / Story N.N" in evergreen committed docs outside of tracking files.
   - Apply from: Story 2.1 onward

3. **Real-browser keyboard verification for a11y focus behaviors**
   - Action: For any story that adds or modifies focus-dependent UI (skip links, tooltips on icon controls, modal focus traps, drawer open/close), verification must confirm the behavior positively with system focus present in a real browser — not in a headless preview environment where `document.hasFocus()` may be false.
   - Owner: Dev Agent (Story 1.3 pattern; document in QA notes)
   - Success criteria: Dev Agent Record states explicitly that focus behavior was verified with system focus confirmed present.
   - Apply from: Any future story touching focus-dependent shell or modal components

### Technical Debt

1. **`verify:lockfiles` guard is untested (HIGHEST PRIORITY)**
   - The guard is the only bespoke verification logic from Epic 1 and its failure path has no automated test. The guard was hardened in review but the hardening itself is not regression-tested.
   - Owner: Dev (first story to initialize the test runner / TEA `testarch-framework`)
   - Priority: HIGH — write this as the first unit test once the test harness lands in Epic 2
   - Blocked by: Real test runner (Epic 2 / testarch-framework)

2. **Client-side service-role import guard (lint/CI)**
   - The "never `NEXT_PUBLIC_` service-role, never import into client paths" rule is prose-only. No lint rule or CI check prevents a future careless import.
   - Owner: Dev (Story 2.1 auth/tenant-context — when env vars are first consumed in code)
   - Priority: MEDIUM — add an ESLint rule or grep-based CI check at the point code begins reading these vars
   - Blocked by: Epic 2 (env consumption lands in 2.1)

3. **Non-hermetic `next/font/google` build fetch**
   - `pnpm build` fetches Geist from Google Fonts over the network. On a restricted-network CI environment this will fail. The monorepo note documents it; the fix (switch to `next/font/local`) is deferred.
   - Owner: Future CI-hardening story
   - Priority: LOW — acceptable for Phase A internal pilot; revisit before external beta

4. **Whole shell is a single client island**
   - `(app)/layout.tsx` delegates to a `"use client"` `AppShell.tsx`, forfeiting App Router server-layout streaming and RSC benefits for the navigation chrome.
   - Owner: Future refactor story (when auth/tenant context lands in Epic 2 and the shell grows)
   - Priority: LOW — shell is small; defer until it justifies splitting

5. **Drawer link focus after navigation**
   - `handleDrawerNavigate` closes the drawer and relies on Next.js client navigation to move focus, which `next/link` does not reliably do. Focus can fall to `<body>`.
   - Owner: Future route-transition/focus story (holistic fix alongside Epic 2 auth/route changes)
   - Priority: LOW — no current blocking keyboard path

6. **Top-bar tenant/user region absent**
   - The slim top bar renders only hamburger + page title + empty primary-action slot. The UX spec calls for neutral tenant/user placeholders.
   - Owner: Story 2.1 (Epic 2 — auth/tenant context resolution)
   - Priority: MED — Epic 2 story 2.1 is the designated owner

7. **Dark-mode / forced-colors / high-contrast support**
   - The shell is hardcoded-light (`#ffffff`/`#171717`). OS dark-mode users and Windows high-contrast users get an unthemed experience.
   - Owner: Future theming / accessibility pass (post Phase A pilot)
   - Priority: LOW — accepted Phase A posture; revisit for external beta

8. **Hardcoded plan numbers in `.env.example` and `local-setup.md`**
   - `.env.example:47` and `local-setup.md:264,293` attribute behaviors to "Epic 8" and "Story 2.2" without spec backing. If the plan shifts these go stale.
   - Owner: SM or docs-maintenance pass when those epics are planned
   - Priority: LOW — no current behavior affected; label as a known staleness risk

## Key Takeaways

1. **Forward-dated version pins are real; adversarial reviewers have a training-cutoff blind spot.** Cross-check claimed "non-existent" versions against the actual repo before acting on adversarial findings.

2. **The scope guardrail architecture works.** Four stories, zero deferred-module leakage, one structural enforcement point (typed `nav-items.ts` with a comment gate). This pattern is the template for every future scope boundary.

3. **The `verify:lockfiles` guard must be the first real unit test when the harness lands.** It is the only bespoke logic in Epic 1 that has no automated regression coverage.

4. **Reference architecture sections, not plan positions, in evergreen docs.** Plan numbers go stale; section numbers are stable.

5. **Headless preview is unreliable for focus-dependent a11y behaviors.** Real-browser keyboard verification with system focus confirmed is required for skip links, tooltips, and focus traps.
