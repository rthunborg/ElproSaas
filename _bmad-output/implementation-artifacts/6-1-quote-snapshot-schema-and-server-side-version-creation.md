# Story 6.1: Quote Snapshot Schema And Server-Side Version Creation

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a tenant admin,
I want to create a draft quote version from a calculation snapshot,
so that customer-visible quote content is preserved independently from mutable calculation/settings data.

## Acceptance Criteria

1. **Given** quote migrations, **when** the database resets from empty, **then** `quotes`, `quote_versions`, `quote_version_lines`, `quote_version_attachments`, and `quote_events` (plus the tenant-scoped counter table `tenant_counters`) are created with tenant ownership (direct `tenant_id`), COMPOSITE same-tenant parent FKs, lifecycle state, and immutable snapshot fields, each with enable+`force` RLS + own-tenant (`is_tenant_admin`) SELECT/INSERT/UPDATE policies + `anon → none` GRANTs + enrollment in `TENANT_TABLES` (H4 gate green), **AND** NO Fortnox/invoice/customer-portal/external-mapping tables are created. [Source: epics.md#Story 6.1 AC1; architecture.md#7 (v0 table list: tenant_counters/quotes/quote_versions/quote_version_lines/quote_version_attachments/quote_events all IN), #9 (RLS test matrix); test-design-epic-6.md#6.1-INT-01/6.1-RLS-01/02, R-601; project-context.md#Architecture Rules (every tenant-owned table: direct tenant_id + enable+force RLS + own-tenant policies + explicit GRANTs incl. anon→none + TENANT_TABLES enrollment; composite same-tenant FK needs parent unique(id,tenant_id))]
2. **Given** a calculation is ready for a quote, **when** `createQuoteVersionFromCalculation` runs, **then** it snapshots — BY COPY-OF-VALUE, not by live reference — the full §11 checklist: customer/facility/contact display data, FULL company identity (org_nr/address/postal/city/email/phone/logo — NOT the identity-partial settings snapshot variant), quote terms text + sign-off state (`approved_at` VERBATIM), line/section display model, base/option(tillval)/VAT/deduction totals + accepted-price basis, VAT/tax assumptions, selected attachment metadata, warnings captured at snapshot time, and source calculation id + snapshot timestamp — and a foreign calculation id or a foreign attachment/file id is rejected with `TENANT_ACCESS_DENIED`. Mutating any source (calc rows / pricing / settings / terms / CRM) AFTER creation leaves the snapshot byte-unchanged (behavioral freeze). [Source: epics.md#Story 6.1 AC2 + Security/RLS Impact; architecture.md#11 (quote version snapshot list), #10 (integer öre / VAT bp); ADR-A005 (immutable quote version); test-design-epic-6.md#6.1-INT-02/03/04, #6.1-UNIT-01, #6.1-GOLDEN-01, R-602/R-603; deferred-work.md#epic-3 (CompanySettingsSnapshot identity-PARTIAL — Epic 6 captures FULL identity); project-context.md#Money/Tax rules (frozen-snapshot-by-copy discipline; capture STATE, compute nothing)]
3. **Given** quote numbering is needed, **when** the draft version is created, **then** tenant-scoped quote number allocation is server-side and race-safe — allocated inside the SAME narrow Postgres RPC transaction as the quote/version/line/event insertion, against `tenant_counters` (row lock / atomic increment), never client-side, with tenant B's sequence independent of tenant A's. Concurrent creations within one tenant yield unique numbers. [Source: epics.md#Story 6.1 AC3 + Technical Notes (narrow RPC for allocation + insertion; SECURITY INVOKER unless a separately-approved DEFINER design); architecture.md#ADR-A009 (narrow RPC), #24 (quote-numbering = tenant-scoped server counter; DISPLAY format is an open owner question, must not become a data-model blocker); test-design-epic-6.md#6.1-INT-05, #6.1-DOCS-01, R-604; epic-5-retro-2026-07-03.md#Preparation Needed (spike the tenant-scoped quote-numbering RPC/sequence pattern before 6.1)]
