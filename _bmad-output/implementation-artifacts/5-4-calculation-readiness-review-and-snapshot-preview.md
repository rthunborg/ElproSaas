# Story 5.4: Calculation Readiness Review And Snapshot Preview

Status: done

## Story

As a tenant admin,
I want calculation readiness warnings and a snapshot preview before creating a quote,
so that I can catch unsafe customer commitments before they are versioned.

## Acceptance Criteria

1. **Given** a calculation with missing or risky data, **when** readiness checks run, **then** BLOCKING issues are separated from WARNINGS via a PURE, unit-testable classifier (extracted from any `"use client"` component — the coverage-shape lesson), **AND** warnings cover: low margin (TB% below a threshold), missing customer/facility/contact where relevant, empty sections, zero-price rows, missing work role on labor rows, unresolved VAT/tax assumptions, ROT/grön-teknik sign-off, hidden rows included in totals, and missing required files. Each condition maps to an explicit rule-table entry with a fixed blocker-vs-warning classification (one unit case per condition). Tax/ROT/grön warnings carry the engine's `requiresSignOff` posture and are framed as an ESTIMATE requiring sign-off — a deduction is NEVER rendered approved/legally-final. [Source: epics.md#Story 5.4 AC1; test-design-epic-5.md#5.4-UNIT-01/02/03/04, R-509; ux-design-specification.md#Readiness and safety (blocking separated from warnings; the exact warning list); src/lib/money (estimateDeduction requiresSignOff); owner-decisions-applied-2026-06-18.md#Epic 5·5.4/5.5 (margin warning = TB% vs a global threshold; hidden rows DO count)]
2. **Given** the admin chooses to create a quote version, **when** the pre-quote review opens, **then** it shows customer/facility/contact, sections (respecting each section's `display_mode`: detailed/summary/text_only), VISIBLE vs HIDDEN row handling, options/tillval (selected vs unselected), totals (net/VAT/gross via `@/lib/money`), VAT display (per the resolved tenant/customer posture), tax assumptions (unapproved + sign-off framing), terms, selected attachments, and the WARNINGS captured at snapshot time — and BLOCKING issues GATE the "create quote version" affordance (a calc with an unresolved blocker cannot proceed to versioning; warnings do not silently disappear). This story PREPARES the snapshot-preview INPUTS — it does NOT create the quote version (that command is Epic 6). [Source: epics.md#Story 5.4 AC2 + Technical Notes (prepares inputs, does not create versions — Epic 6 owns the command); test-design-epic-5.md#5.4-E2E-01/02, R-509; ux-design-specification.md#Readiness and safety (snapshot review content list); src/features/calculations/totals.ts (the totals authority to reuse)]
3. **Given** a sent quote already exists for this calculation, **when** calculation changes affect customer-visible content, **then** the UI EXPLAINS (in approved-pending Swedish copy) that a NEW quote version is required rather than mutating the sent version. This story renders the MESSAGE only; the actual immutability ENFORCEMENT (block the mutation / force a new version) is Epic 6's `mark-sent` + `new-version` commands. Because no `quotes`/`quote_versions` table exists yet (Epic 6 owns it), the "a sent quote exists" signal is a documented forward-seam: render the explanatory copy where the create-quote affordance lives, gated on whatever sent-state signal is available (today: none → the message is a static/placeholder affordance the E2E asserts is PRESENT, per 5.4-E2E-03 "message present; enforcement is Epic 6").
