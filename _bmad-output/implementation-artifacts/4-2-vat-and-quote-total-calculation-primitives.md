# Story 4.2: VAT And Quote Total Calculation Primitives

Status: review

## Story

As a tenant admin,
I want VAT and quote totals to be calculated from explicit assumptions,
so that draft calculations and quote snapshots show explainable customer-facing totals.

## Acceptance Criteria

1. **Given** a line with a net amount (integer öre) and a VAT rate in BASIS POINTS, **when** VAT is calculated, **then** VAT amount is rounded PER LINE under the conservative pilot policy (round-half-away-from-zero, the SAME single half-rounding mode Story 4.1 pinned — computed as `roundToOre(lineNetOre * vatRateBp / 10000)`, NOT a `* 1.25` shortcut and NOT a hidden `0.25`/`25` literal), **and** section/quote totals SUM the already-rounded per-line VAT values (sum-of-rounded, never round-of-sum) using the Story 4.1 `sumOre` primitive, so a section VAT total = the sum of the rounded line VAT values and diverges from a naive round-of-the-summed-VAT exactly where the pilot policy says it should. The VAT rate ALWAYS flows in as a basis-point input (from tenant `company_settings.vat_rate_bp` / a snapshot) — the engine invents no rate and holds no percent constant. [Source: epics.md#Story 4.2 AC1 + Technical Notes ("Store VAT rates as basis points. Do not rely on hidden 25% constants"); architecture.md#10 Rounding ("Calculate VAT per line from rounded line net and snapshotted VAT basis points, then round to nearest öre"; "Sum rounded line values for section and quote totals") + #10 Storage (VAT rates use basis points, e.g. 2500 for 25.00%); test-design-epic-4.md R-403 + R-404 + 4.2-UNIT-01 + 4.2-GOLDEN-01; project-context.md#Money, Tax, And Quote Rules (VAT rate is BASIS POINTS, NEVER a code literal; "Reuse `isOreAmount` for every new öre field")]

2. **Given** VAT display modes, **when** totals are rendered for admin review, **then** excl-VAT, incl-VAT, and both-display assumptions are represented as PURE derived views (e.g. `{ netOre, vatOre, grossOre }` where `grossOre = netOre + vatOre`) WITHOUT changing the stored source totals — the underlying net/VAT öre values are the immutable source of truth and switching display mode is a presentation-only transform that re-derives, never mutates, them. The engine exposes the three views over the same computed net + VAT öre; a round-trip through any display mode returns the identical stored source öre. The tenant `default_vat_display` enum (`company_togglable` / `company_excl`) is consumed/interpreted AS-IS as a presentation input; the "private customer → ALWAYS incl-VAT (not togglable)" rule is an Epic-4 presentation INVARIANT the display layer honours — build it as a conservative, sign-off-pending assumption, do NOT encode it as legally-approved fact (see Sign-Off Q2).
