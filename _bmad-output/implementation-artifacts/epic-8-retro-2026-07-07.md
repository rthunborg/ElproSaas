### Key Insights And Patterns

Bob (Scrum Master): "Here's what stood out across all five stories, the epic-boundary review, and the NFR/trace gates."

1. **The single Phase A file model (R-814) held under four epics of real pressure.** Story 8.1 shipped the ONE model; Epic 6's PDF storage, Epic 7's evidence/job files, and this epic's full upload/preview/lock/index surface all extended it with zero competing model ever appearing. This is a standing-contract discipline win worth naming explicitly at epic close, not just assuming it will keep holding.

2. **A deferred AC gap that names a specific future story as its owner is only safe if someone checks that story's actual scope statement can absorb the fix.** The acceptance-evidence-upload lifecycle gate is the sharpest lesson of this epic: 8.2 named 8.4 as the fix owner, but 8.4's scope, as written, excluded upload entirely. This is a NEW failure mode not seen in Epics 6 or 7's retro history — a story-to-story deferral silently falling through a scope gap rather than a within-story testing gap.

3. **The dedicated whole-epic review lens is now proven THREE epics running as the thing that catches cross-story gaps per-chunk review misses.** Epic 7's retro named this pattern (the 7.1↔7.3 `owner_type` mismatch); Epic 8 repeats it in a new shape (the 8.2→8.4 deferral routing gap). This is now a load-bearing, not incidental, part of the review process.

4. **Stale `describe.skip` RED PHASE banners on already-green test bodies are a distinct, mechanically-preventable false-positive class.** Three separate suites carried this exact contradiction and fooled every blind reviewer pass. A lint checking banner text against actual `.skip`/`.only` state would eliminate the whole class rather than relying on manual catch.

5. **Test titles that claim more than their bodies prove keep recurring (now 2 epics running).** Epic 7 had this pattern; Epic 8's "atomicity" test that actually proved lock precision repeats it. This is a distinct pattern from the stale-banner issue — it's about semantic honesty of what a passing test demonstrates, not about skip-state.

6. **The two-layer lock pattern is now proven at a THIRD scope (files) without forking the `QV409`/`AR704` family**, extending the "dual-layer immutability, proven twice, measurably better" trajectory from Epic 7's retro into a third confirmed instance. The design-discuss-ahead-of-create-story discipline Epic 7's retro explicitly asked for (sibling trigger vs. extend) was applied and worked.

7. **Trigger-timing subtleties in Postgres (transaction_timestamp vs. wall time; OLD vs. NEW in an UPDATE arm) are becoming a recurring class of non-obvious defect this project keeps discovering fresh each time a new lock/apply trigger is designed**, rather than a documented pattern engineers can check against up front.
