## Story

As a pilot operator,
I want representative money and tax fixtures,
so that calculation and quote behavior can be compared against known old/new expectations.

## Acceptance Criteria

1. **Given** anonymized fixture data, **when** the golden tests run, **then** the pack COVERS every AC1 category in one reviewable oracle: **regular VAT** (0/6/12/25 % as bp), **ROT**, **grön teknik**, **caps** (at/above/below), **invalid ROT×grön mixes** (blocked, never summed), **options/tillval** inclusion, **hidden rows** (which count toward basis/totals), **fractional quantities**, **rounding** (line-level, half-away-from-zero, sum-of-rounded), and **accepted-price deltas** — AND every expected value is explicitly labelled `old-lovable` (documented old Lovable behavior), `new-expected` (the pilot's explicit new behavior), or `documented-delta` (an intentional divergence from Lovable). A golden FAILURE must point to the affected assumption/delta, not surface as an unexplained diff (R-410). [Source: epics.md#Story 4.4 AC1; test-design-epic-4.md 4.4-GOLDEN-01 (P0) + 4.4-GOLDEN-02 (P0) + R-410; Coverage Plan Exit Criteria ("Golden pack complete + labelled: covers regular VAT, ROT, grön teknik, caps, invalid mixes, options/tillval, hidden rows, fractional quantities, rounding, and accepted-price deltas; each expected value labelled old-Lovable / new-expected / documented-delta")]

2. **Given** fixture source material, **when** it is committed, **then** it contains **NO real names, emails, phone numbers, addresses, personnummer, organization numbers, secrets, `.env` values, or raw customer files** unless explicitly approved. The privacy scan is a CI-run assertion over the DATA payload (not the `_doc` prose) that REUSES + EXTENDS the existing golden PII/secret scan: personnummer/orgnr shape `\d{6}-\d{4}`, non-`example.test` email `@(?!example\.test\b)…`, and `secret|password|api_key` — extended with an explicit **orgnr shape** guard and the additional PII classes AC2 names (phone, address). Money/rate/cap/öre numbers ONLY (R-411). [Source: epics.md#Story 4.4 AC2 + Security/RLS Impact ("Fixture privacy is required; no live tenant data"); test-design-epic-4.md 4.4-UNIT-01 (P0) + R-411 + Non-Negotiable ("No real PII/secret in any golden fixture (CI scan green)"); existing scan in `tests/unit/lib/money/vat.golden.test.ts` + `tax.golden.test.ts` + `rounding.golden.test.ts`]

3. **Given** a future money/tax implementation changes behavior, **when** the tests run, **then** golden FAILURES point to the affected assumption or expected delta — the fixtures are STRUCTURED and REVIEWABLE with a contract-shape guard: each fixture file carries a `_doc` provenance note, a `policy` block, and cases whose `origin` label + `note` make the diff explainable, and a UNIT schema-shape assertion FAILS a malformed fixture (missing `origin`, missing expected value, or an unlabelled case) so the oracle cannot silently rot (R-410). [Source: epics.md#Story 4.4 AC3 + Technical Notes ("Keep fixtures structured and reviewable"); test-design-epic-4.md 4.4-UNIT-02 (P1, "Fixtures structured (old/new/delta) + reviewable; contract-shape assertions on the fixture schema") + Testability Note 4 ("The golden pack is only as good as its labelling … an unlabelled golden is a silent-regression trap")]

4. **Given** this story is the FIRST golden-master fixture FOUNDATION and a PURE test/fixture story, **when** the deliverable lands, **then** it adds ONLY anonymized golden fixtures under `tests/fixtures/golden/money/**` + a golden-pack test under `tests/unit/lib/money/**` (so `pnpm run test:unit` actually runs it — see Critical Constraints) + optional DOCS residual notes — and builds **NO** database schema/migration, **NO** new dependency, **NO** `.env` edit, **NO** new nav item/route/UI, **NO** change to `src/lib/money` engine behavior (it CONSUMES the frozen 4.1/4.2/4.3 primitives as the oracle, it does NOT re-implement or fork them), **NO** calculation rows (Epic 5), and **NO** quote-version/acceptance PERSISTENCE (Epics 6-7 — the "accepted-price delta" is a fixture SHAPE only). All existing suites (money, VAT, tax, snapshots golden, service-role/bundle containment) MUST stay green. [Source: epics.md#Story 4.4 Technical Notes ("Store under `tests/fixtures/golden/lovable/**` and `tests/golden/**` or approved equivalents"), Test Requirements ("Golden tests plus fixture privacy/no-secret checks"), Migration/Coexistence ("first golden-master fixture foundation"); test-design-epic-4.md Not in Scope (calc UX = Epic 5; quote persistence = Epic 6; acceptance/accepted-price immutability = Epic 7 — "Epic 4 only supplies the golden 'accepted-price delta' fixture SHAPE (4.4 AC1)"); Execution Strategy (Epic 4 adds NO DB/UI surface)]
