# Story 6.3: Quote PDF Generation From Snapshot

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a tenant admin,
I want to generate and preview a quote PDF from the selected quote version snapshot,
so that the customer-facing document matches the immutable version data.

## Acceptance Criteria

1. **Given** a quote version, **when** PDF generation runs, **then** it reads ONLY `quote_versions`, `quote_version_lines`, `quote_version_attachments`, and file-metadata snapshot data — and DOES NOT read mutable `customers`, `company_settings`, `quote_terms`, `calculation_*` rows, `work_roles`, or `articles` as source of truth. Mutating any of those mutable sources AFTER a version's snapshot and THEN regenerating the PDF leaves the customer-visible output byte-comparable (the canonical Epic-6 negative: PDF disagreeing with the immutable commitment is the headline bug). Every money/VAT/total/line value the PDF prints is READ VERBATIM from the frozen `quote_versions`/`quote_version_lines` rows and formatted öre→kronor via the SINGLE existing formatter — never recomputed. Internal fields (`unit_cost_ore`, margin/markup, `internal_note`) NEVER reach the PDF (they are not even present on the snapshot rows — R-607; the `QuotePdfViewModel` input surface is provably snapshot-only). [Source: epics.md#Story 6.3 AC1 + Money/Tax Impact (HIGH); architecture.md#12 (PDF reads only the four snapshot sources; source-of-truth rule), #11 (snapshot field list); test-design-epic-6.md#6.3-INT-01/6.3-UNIT-01/6.3-GOLDEN-01, R-606/R-607]
2. **Given** PDF generation states, **when** the admin views the quote, **then** the states `not_generated`, `generating`, `generated`, `failed`, `retry`, and `preview`/`download` are all VISIBLE and ACCESSIBLE (keyboard-operable controls with accessible names; a non-color status cue). A `failed` state offers a retry affordance; a `generated` state offers preview + download (via a short-lived signed URL, never a public URL). [Source: epics.md#Story 6.3 AC2; architecture.md#12 (render status `not_generated`/`generating`/`generated`/`failed`; retry for draft/sent without mutating snapshot); test-design-epic-6.md#6.3-E2E-01/6.3-E2E-02, R-613]
3. **Given** a generated PDF, **when** it is stored, **then** it is stored as a PRIVATE file tied to the quote version through the Story 8.1 file foundation (`files`/`file_links`, private bucket, SERVER-derived object path, signed access) — with a `files` metadata row, a `file_links` row (`owner_type='quote_version'`, `owner_id=<quote_version_id>`, `purpose='quote_pdf'`), a `quote_events` lifecycle event, and an `audit_events` record, all written consistently (transactional or verified-compensated). The PDF file/metadata is NOT reachable cross-tenant or anonymously (cross-tenant + anon access to the file/metadata is REJECTED; no public URL surface). 6.3 MUST NOT introduce its own file/storage/metadata model. [Source: epics.md#Story 6.3 AC3 + Security/RLS Impact (HIGH); architecture.md#12 (store in private Storage; write files/file_links/quote_events/audit_events), #14 (files/file_links model, private buckets, server-derived paths, signed URLs, purpose=quote_pdf); test-design-epic-6.md#6.3-INT-02, R-611]
