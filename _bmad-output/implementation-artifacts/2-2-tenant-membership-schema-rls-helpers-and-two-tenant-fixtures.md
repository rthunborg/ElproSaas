## Story

As an implementation lead,
I want tenant ownership and membership enforced in the database,
so that later CRM, quote, file, and job data cannot leak across tenants.

## Acceptance Criteria

1. **Given** Phase A migrations for the tenant foundation, **when** the database is reset from empty (`supabase db reset`), **then** the migration applies cleanly and creates `tenants`, `tenant_memberships`, and the required helper functions (`is_active_tenant_member(uuid)`, `is_tenant_admin(uuid)`), **and** the `tenant_memberships.role` is constrained to `tenant_admin` for Phase A (any other role value is rejected by a DB constraint).
2. **Given** two tenants and two `tenant_admin` users created by the test factories, **when** Tenant A's user queries Tenant B's `tenant_memberships` or `tenants` rows, **then** RLS denies the read (zero rows returned), **and** Tenant A cannot INSERT, UPDATE, or DELETE Tenant B rows, **and** Tenant A cannot spoof Tenant B ownership (e.g. insert a row carrying Tenant B's `tenant_id`).
3. **Given** an authenticated user, **when** that user attempts to self-grant or escalate membership (insert their own `tenant_memberships` row, or UPDATE their own `role`/`status`/`tenant_id`) through the app (anon-key) path, **then** RLS denies the write (privilege escalation is impossible through normal app paths).
4. **Given** the `is_active_tenant_member` / `is_tenant_admin` helpers are `SECURITY DEFINER`, **when** they are declared, **then** each has a fixed `search_path` (`set search_path = ''` or schema-qualified), is covered by a negative test proving a malicious object on the search path cannot alter the result, **and** an explicit review note is recorded.
5. **Given** the local Supabase stack and a real test runner now exist, **when** the test suite runs against local Supabase only (`supabase db reset` first), **then** test-only factories provision a fresh two-tenant pair (two `tenants`, two auth users, two `active` `tenant_admin` memberships) PER worker (no shared mutable fixture), **and** the gated Story 2.1 DB-backed integration scaffold (`tests/integration/server/auth/resolve-tenant-context.int.test.ts`) is un-skipped, wired to these factories, and passes — proving the AC1-AC4 properties Story 2.1 deferred here.
6. **Given** a later story adds a tenant-owned business table, **when** that story is implemented, **then** it reuses these helper predicates and adds table-specific cross-tenant RLS negative tests using the same factory pattern (this story establishes the reusable pattern; the standing inventory gate that enforces enrollment is Story 2.4, not this story).
