### Key Insights And Patterns

**Insight 1 — The GRANT-alongside-RLS checklist is load-bearing.**
New `public` tables on this Supabase stack are NOT auto-exposed to the Data API roles. RLS only narrows an already-granted role. Adding a tenant-owned table WITHOUT explicit GRANTs surfaces as `42501 permission denied` on the app-path write — a STRONGER guarantee than RLS zero-rows, but only if the test suite asserts the mechanism. The per-table checklist (authenticated→SELECT, service_role→DML-as-appropriate, anon→none) must be the first thing every Epic 3-9 story does when creating a table.

**Insight 2 — Red-phase ATDD scaffolds must use dynamic-import-inside-skipped-body + tolerant beforeAll + tsconfig exclude.**
`node:test` fails the whole file on a load-time import throw BEFORE per-test `{skip}` applies. `Vitest` top-level `beforeAll` runs even under `describe.skip`. The established pattern (dynamic import in skipped body + `@ts-nocheck` + exclude from tsconfig until source exists) is now documented in the retro notes and applied consistently.

**Insight 3 — `force-dynamic` is mandatory for protected routes, and ONLY the build gate catches its absence.**
Adding a server auth boundary silently converts previously-static `(app)` pages to needing per-request env/cookies. `export const dynamic = 'force-dynamic'` is mandatory; typecheck and lint do not catch its absence. Every Epic 3+ protected route must set it and the `pnpm build` gate must be run to verify.

**Insight 4 — Broadening a fail-closed gate requires an exhaustive type model.**
The H4 inventory gate decision to broaden detection (Story 2.4 iter-1) was correct but created new partial-coverage edges. The fix — `switch(table) + assertNever` making an unenrolled table a typecheck error — is the pattern to follow for any future "broadening" of a fail-closed safety gate.

**Insight 5 — The append-only trigger vs tenant cascade-delete interaction.**
The `audit_events_append_only` BEFORE UPDATE OR DELETE trigger also blocks tenant on-delete-cascade in `cleanupFixture`'s tenant delete, causing audit rows to accumulate across non-reset runs. With hardcoded correlation IDs in some DB-backed audit tests, this makes `envelope-audit-write.int` fail on a stale DB (clean DB reset + CI are green). Fix: let the trigger permit cascade deletes OR have `cleanupFixture` privileged-delete audit rows before the tenant. Deferred to a test-hardening pass.

## Key Takeaways

1. **Server-resolved tenant context is the load-bearing security property of the entire platform.** Every later epic's tenant isolation rests on `resolveTenantContext` and the `tenant_id`-carrying table convention. Weaken either and you weaken everything. The H4 gate is what makes this enforceable going forward.

2. **The GRANT+RLS combination is what makes isolation real.** RLS alone (without explicit GRANTs) is not enough on this Supabase stack — new `public` tables are not auto-exposed to the Data API roles, and RLS only narrows what is already granted. The per-table GRANT checklist is mandatory from Epic 3 onward.

3. **Fail-closed gates need exhaustive type models to stay fail-closed.** The `assertNever` pattern in the H4 inventory gate's metadata helpers is the right enforcement: a future enrollee that forgets its metadata branch is a typecheck error, not a silently-wrong row.

4. **Data-driven test infrastructure pays compound dividends.** The single `TENANT_TABLES` inventory + the data-driven cross-tenant/anon suites mean a future Epic 3 table enrollment is one data edit, not a copy-pasted suite. This was designed intentionally across Stories 2.2, 2.3, and 2.4.

5. **The test runner (dual `node --test` + Vitest) and the Windows bare-Node orchestrator are standing conventions.** Do not break them, do not chain `&&` in package.json, and do not replace them without a TEA `testarch-framework` re-decision.
