# Story 3.4: Work Roles And Optional Manual Articles

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a tenant admin,
I want to maintain labor work roles and a minimal manual material-article register,
so that calculations can use reusable, tenant-owned prices without any supplier-integration scope.

## Acceptance Criteria

1. **Given** tenant-owned pricing tables, **when** migrations run from an empty database, **then** `work_roles` and `articles` are created, each carrying a DIRECT `tenant_id` (FK → `public.tenants`, `on delete cascade`), money fields stored as INTEGER ÖRE (`bigint`, NEVER float kronor), an active/archive lifecycle column, `created_at`/`updated_at` timestamps (with the EXISTING `public.set_updated_at()` BEFORE UPDATE trigger — reused, never redefined), a `tenant_id` index, enable+FORCE RLS with own-tenant `is_tenant_admin` SELECT/INSERT/UPDATE policies (NO delete policy — archive over hard delete), and explicit GRANTs (`authenticated → SELECT/INSERT/UPDATE`, `service_role → DML`, `anon → none`). UNLIKE Story 3.3's settings tables, these are MANY-rows-per-tenant collections (NO `unique (tenant_id)`). [Source: epics.md#Story 3.4 AC1; architecture.md#6 (direct tenant_id), #7 (work_roles IN, articles OPTIONAL→IN), #10 (öre bigint), #22; supabase/migrations/20260630130000_company_settings_and_quote_terms.sql (the table/trigger/index/grant/RLS template to mirror)]
2. **Given** work-role management, **when** the admin creates / updates / archives / reactivates a role, **then** the row carries `display_name`, `cost_rate_ore bigint` and `sell_rate_ore bigint` (the cost + sell HOURLY RATES, integer öre), an `is_active` (or `archived_at`) lifecycle flag, and source timestamps — all tenant-owned and AUDITED (one append-only `audit_events` row per critical change via the envelope's `writeAuditEvent` DEFINER path, metadata allow-listed `{ targetId }` — NO PII/rate value in metadata). Rates are validated as NON-NEGATIVE integers in öre (reject floats, negatives, overflow beyond a safe `bigint`-fitting bound, and locale-comma/decimal-string inputs) → `VALIDATION_FAILED`. NO calculation is performed on the rates (Epic 4 owns the money/VAT engine) — they are STORED as reusable prices only. [Source: epics.md#Story 3.4 AC1 + Test Requirements (money input validation using integer öre; audit tests for pricing changes); architecture.md#5 (upsertWorkRole/archiveWorkRole — "Audit pricing change"), #10 (öre bigint); epic-3 retro-note (INTEGER money — cost/sell hourly RATES are money → integer öre, reject floats/negatives/overflow/locale-comma; NO calculation engine — store reusable prices only); owner-decisions-applied-2026-06-18.md#Story 3.4 (work roles priceable; integer öre)]
3. **Given** articles are enabled by this implementation story (owner decision 2026-06-18 confirms the reusable article/material register is IN scope for the pilot), **when** the admin manages article/material records via `upsertArticle`/`archiveArticle`, **then** articles are MANUAL, MINIMAL, tenant-owned (e.g. `name`, optional `sku`/`unit`, a `unit_price_ore bigint` integer-öre price, `is_active`/`archived_at`, timestamps) and contain NO supplier credentials, supplier sync fields, supplier IDs, imports, APIs, EDI, or external mappings. The schema, command, AND tests ENFORCE this no-supplier-scope (a column-name guard like the CRM no-supplier-scope assertion, asserting the `articles` column set contains no `supplier`/`sync`/`import`/`external`/`api`/`fortnox`/`vendor`/`edi` token). [Source: epics.md#Story 3.4 AC2 + Stop Conditions ("articles … contain no supplier credentials, supplier sync fields, imports, APIs, or external mappings"; "Stop if article work expands into supplier APIs/imports/credentials"); architecture.md#7 (articles: "No supplier IDs, credentials, imports, or APIs"), #5 (upsertArticle — "No supplier behavior"), #25/§Supplier-Pricing boundary (Not in Phase A: supplier credentials/IDs/APIs/imports/EDI/sync); epic-3 retro-note (HARD NON-NEGOTIABLE — articles have NO supplier scope; the schema + command + tests enforce it via a column-name guard); owner-decisions-applied-2026-06-18.md#Story 3.4 (articles IN scope)]
4. **Given** tenant A and tenant B pricing data, **when** tenant A attempts to read/write tenant B `work_roles`/`articles` rows (cross-tenant SELECT, INSERT spoofing B's `tenant_id`, UPDATE of B's row, DELETE) OR to spoof a parent/tenant, **then** RLS and the command validation reject it: a cross-tenant SELECT/UPDATE sees zero rows (RLS USING invisibility — `updateDenialKind` = `"rls-invisible"`: zero-rows-affected PLUS an independent BYPASSRLS re-read proving B's row is UNCHANGED), a cross-tenant INSERT fails the WITH CHECK (`42501`), DELETE stays `"privilege"` (no DELETE grant), and anon SELECT/INSERT/UPDATE/DELETE is denied (anon-DML-empty). Both tables are enrolled in `TENANT_TABLES` (cross-tenant + anon-path suites) and the H4 inventory gate, with assert-the-mechanism negatives. [Source: epics.md#Story 3.4 AC3 (cross-tenant access/parent spoofing rejected); architecture.md#9 (RLS test matrix); project-context.md#Security Regression Harness Rules (H4 single enrollment contract; anon-path; cross-tenant negatives); epic-3 retro-note (every new tenant-owned table enrolled in H4 — cross-tenant + anon-DML seams; assert-the-mechanism; migration-reset exact-policy enumeration extended; assertNever inventory switch)]
5. **Given** the pricing settings UI at `/settings/pricing` (Prissättning), **when** the admin opens it, **then** a real `export const dynamic = "force-dynamic"` screen exists that lists/edits work roles and articles, reading via the per-request cookie-bound RLS client and writing ONLY through the envelope command(s) via a `"use server"` action — NEVER a direct client write, NEVER a service-role key. Money inputs display kronor (e.g. "850,00 kr/tim") but STORE integer öre (convert at the boundary, mirroring the 3.3 bp↔percent boundary helper); validation is programmatically associated (`aria-invalid`/`aria-describedby` → error node, `aria-live` summary), input preserved on failure, no color-only signalling, and the typed `Result` maps to the documented UI states (`VALIDATION_FAILED` → field/summary; `TENANT_ACCESS_DENIED` → generic; transient `SERVER_ERROR` → retryable, NOT a permanent denial). Route auth is the EXISTING `(app)` server-layout boundary; this story adds NO new auth mechanism and NO new nav item (`nav-items.ts` stays EXACTLY the seven IN-scope modules). [Source: architecture.md#4 (/settings/pricing — Prissättning — Work roles and optional minimal articles); ux-design-specification.md#4 (Pricing settings: work roles + optional articles), #9 (Settings states: invalid price/margin), #10 (a11y); 3-3 story (the force-dynamic server page + useActionState + "use server" action + FormField a11y + bp↔percent boundary pattern to reuse); project-context.md#Framework-Specific Rules (force-dynamic; nav exactly seven; auth server-side)]
6. **Given** work-role + article values that DOWNSTREAM calculations/quotes will reference, **when** they are stored, **then** they are SNAPSHOTTABLE — a stable, frozen-at-use shape (source id + display name + monetary values in öre + source timestamp + tenant ownership) that Story 3.5's snapshot CONTRACT and Epics 5-6 can freeze. This story ONLY stores the values in a snapshot-friendly shape; it does NOT build the snapshot mechanism, a snapshot table, or any recompute/freeze logic (that is Story 3.5 + Epic 4-6). NO calculation engine, NO ROT/grön teknik, NO free-entry calculation rows (that is Epic 5; work roles are merely ONE of the two labor pricing PATHS Epic 5 will offer). [Source: epics.md#Story 3.4 Technical Notes (work role and article values must be snapshottable when used) + Money/Tax/Quote Impact (prices are source inputs for calculation rows and quote snapshots); architecture.md#11 (snapshot includes work-role prices + article prices), #7 (work_roles: "selected values are snapshotted in rows/quotes"); epic-3 retro-note (SNAPSHOT SOURCE — store values in a snapshot-friendly shape; the snapshot-source CONTRACT is Story 3.5's job; 3-4 only stores the values); owner-decisions-applied-2026-06-18.md#Story 3.4 (labor priceable both via reusable work roles AND free entry — free-entry is Epic 5's calculation row, not this story); #Story 3.5 (snapshot contract must cover articles + work roles)]
