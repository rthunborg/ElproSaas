## File/link/signing invariants

One result is one exact live authorized`file_link`, not one file. Server derives owner/module/purpose from link metadata and verifies file_id match; a file's other authorized link is not substitute authority for a selected disappeared context. File metadata must be linked/locked, nonarchived and nondeleted; no unlinked reservation or unknown state. Listing safe DTO and any facet/count/label consume the authorized projection only. Default record order is link-created time plus link ID; paginate candidate rows completely before declaring source-filtered exhaustion. Use bounded pages and opaque checked/server-held cursors without hidden owner identity.

Generic `createSignedFileAccess` currently accepts file_id only, enforces Files.View/request tenant/file lifecycle and checked audit attestation, then uses request-bound Storage signer. `previewEntityFileAction` uses file_id only. Prepare/finalize generic SQL checks tenant/file/object/lifecycle, not selected source/link; an unchanged file_id funnel cannot fulfill the new selected-source promise. The new concrete Documents contract uses`document.signedAccess.create`, Documents-specific checked prepare/finalize and a distinct HMAC binding exact link/source/purpose/file/object plus current membership/role rechecks. SQL definer validators use explicit checked authority, never assume nested invoker reads equal caller RLS. SHARE locks, exact locked-graph reconciliation and post-lock revalidation linearize authority with final audit commit; later revocation/HTTP delivery/bearer use has the disclosed residual lifetime. Return no URL when final audit fails. The stored object path/bucket stay server-only; client-supplied paths, owner/module or capabilities are not trusted.

Storage and DB cannot transact atomically. A signed bearer URL may be minted before a final denial; the application must not return it, and must not log/store its raw token in client-facing data. Already issued URLs remain usable under downstream bearer semantics until expiry; current default300s, configurable upper bound86400s in`src/server/storage/signed-access.ts`. Neither design below promises immediate revocation. No proxy/instant invalidation/new retention program is proposed.

Current generic lifecycle allows ordinary draft/linked/locked but excludes archived/deleted and quote_pdf draft. Proposed Documents excludes generic draft reservations at listing/open. Quote10.9 invalidation already archives/unlinks stale PDFs and clears current association; absent fingerprint comparison alone is not a demonstrated reachable stale-PDF defect. Exact quote source/link/current association still matters for owner/parent/link disappearance. Use the existing quote target eligibility, keeping request-bound generic Storage primitive for allowed Documents roles. The server-only quote Sales broker is a narrower existing exception and must not become a general Documents signer or widen Files.View.

Documents provenance branching follows durable`files.artifact_kind`, not the selected link's purpose. Ordinary branch requires null artifact kind. Every quote-PDF artifact requires the strict selected quote_version/quote_pdf link and exact current generated association; an authenticated ordinary-purpose link added by`link_file_with_audit` cannot turn it into ordinary CRM/calculation/snapshot/evidence content. Such a selected context is denied even if another valid PDF link exists. Unknown nonnull kinds and null-kind/quote_pdf-purpose mismatch fail closed. This invariant is explicit in the contract/spec and adversarial tests; generic/direct Storage residual is unchanged.

Archive-over-delete/locks stay authoritative. No byte replacement, lock removal, physical deletion, historical attachment rewrite or restore source-resurrection occurs in20.1.20.2 must finalize its allowed restoration matrix separately.
